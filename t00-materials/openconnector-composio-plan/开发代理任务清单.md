# 开发代理任务清单与启动指令

**关联方案：** `完整实施方案.md`  
**日期：** 2026-10-02  
**状态：** 待执行；本文不是已创建的 Codex 任务列表，也不是代码提交报告。

执行代理角色优先由 Codex 承担，也可以由其他获准开发代理承担。开发、测试和审查应分别提供可核验的产物；任务完成以代码、测试输出与审查结论为准，不以文字描述为准。

## 一、执行边界

工作区未提供时报告环境阻塞，不向任何上游或名称相似的 fork 写入。项目主仓库、用户 Multica fork 和获准 OpenConnector fork 均须记录 URL、remote 与分支。

开始前读取 AGENTS.md、CLAUDE.md、贡献规范、CI 与已有测试命令。记录当前 commit、未提交变更、部署版本和安全约束，不丢弃已有改动。

生产 OAuth 应用、真实密钥、用户账号和写操作不是文档自带授权。测试使用指定账号和资源；不能向生产对象执行发信、删除、发布或资金操作。真实凭据只放获准密钥存储，不写入 PR、日志、截图或方案。

## 二、统一完成标准

每个任务提交：改动范围、关联设计条目、测试命令与结果、风险、未实现项、依赖版本和回滚方式。

适配代码必须有输入验证、明确超时、结构化错误和脱敏。涉及权限的失败路径一律拒绝执行，禁止 fallback 到全权限 Token、默认账号或另一后端。

有外部依赖阻塞时，继续完成可独立验证的部分，并把对应真实联调标记 BLOCKED；不能把 mock 通过写成真实环境通过。

       │    ├─ T06 session策略 ── T07 Multica安全接线

这是逻辑依赖，不要求并行修改同一文件。可先合入接口与 fixture，再将实现分配到独立分支，避免不同代理同时重写认证或 schema。

## T00：工作区与基线预检

**目标：** 确认真实写入目标和可执行环境。

**操作：** 检查 git remote、branch、HEAD、status；读取仓库说明；记录用户部署与方案基线差异；确认是否有 OpenConnector 补丁授权；检查 Go/Node、数据库、容器、CI 和网络能力。

**产物：** `docs/preflight.md`、最小风险清单、初版 compatibility manifest。

**验收：** 三类仓库的读写边界明确；原始未提交改动完整保留；没有使用上游代替用户目标。无工作区则提交阻塞说明，不继续写库。

## T01：冻结契约与真实客户端测试骨架

**依赖：** T00。

**操作：** 按固定 Multica commit 提取真正调用的 API、SDK 请求类型、响应解析、callback、auth config、overlay 和运行时提示词；将 OpenConnector 路由及 schema 保存为带摘要快照；建立真实 SDK 调用测试，不伪造一份同名 SDK。

**特别检查：** 重复 query 参数、嵌套 `auth_config.id`、状态大小写、分页、404 幂等、错误 envelope、未知限制字段、MCP 工具名引用。

**产物：** `contracts/multica-core-v1`、`contracts/openconnector`、接口矩阵和失败 fixture。

**验收：** C01–C06 可运行；未实现接口明确红灯或 unsupported，不用成功 mock 隐藏缺口。

## T02：网关骨架、身份与持久化

**依赖：** T01。

**操作：** 建立 Go 服务、双入口、配置解析、数据库迁移、project/subject/connection/session/execution/outbox/audit 实体；实现控制凭据与会话凭据分离、稳定 ID 归属和跨项目查询约束。

**产物：** 可启动服务、迁移、repository 层测试、健康检查与日志脱敏测试。

**验收：** S01/S04/S05 的基础测试通过；数据库不可用时启动/执行路径不会开放权限；所有执行 Token 只存摘要或必要的加密形式。

## T03：目录与 auth config

**依赖：** T02。

**操作：** 实现 toolkits/auth_configs；只展示准入并已完成授权配置的 provider；维护稳定 auth_config_id；统一分页、搜索与过滤。

**产物：** 目录转换器、provider capability 配置、测试 fixture。

**验收：** C01–C05 通过；无 OAuth client 的 provider 不可连接；provider 改名与配置轮换不导致旧 ID 被意外复用。

## T04：连接页、授权事务与身份确认

**依赖：** T02、T03；生产并发依赖 T05。

**操作：** 实现 CreateLink、原生授权请求关联、服务端结果确认、一次性 verifier ticket、Multica 登录身份确认、最终 callback、CAS 状态变更和孤儿清理；协调两层 state TTL。

**特别检查：** 不从 URL 宣告成功；不猜“最近创建的连接”；创建结果未知不重复发起；晚到回调不复活旧授权。

**产物：** 浏览器流程与后端状态机、身份验证接线、故障恢复任务、端到端录屏或脱敏日志。

**验收：** A01–A06/A08 全通过；A07 在保底模式明确并发受限，生产模式必须通过。

## T05：OpenConnector 可信 subject 授权隔离补丁

**依赖：** T01、T04 接口设计。

**操作：** 在管理鉴权之后增加可选 subject 上下文，统一 create/poll/reconnect/sync 的 owner；默认保持 local-admin。subject 不接受普通 runtime token、浏览器任意参数或 MCP 透传。

**产物：** 独立 PR、旧模式回归、两用户同 provider 并发测试、扩展配置说明。

**验收：** A07 通过；伪造 header 不获得另一用户授权事务；不宣称 owner 扩展已经解决底层全部多租户授权。

**无补丁保底：** 只能启用跨副本 provider 互斥并披露限制，不能静默取消其他用户的 pending 授权。

## T06：会话策略、凭据与撤销

**依赖：** T02、T03。

**操作：** 实现 `/tool_router/session`、精确连接/Action 授权、mcp.headers 扩展、token摘要、generation、TTL、revoke、任务上下文和 outbox；权限为空则拒绝。

**产物：** session API、策略单元测试、异常输入 fuzz/property tests、跨副本撤销测试。

**验收：** S01–S04/S06/S07/S09/S10；项目 Key 不能在 MCP 入口换取或模拟执行权限。

## T07：Multica 最小安全补丁

**依赖：** T04、T06；可先按合同开发。

**操作：** BaseURL/backend 配置、兼容响应头、compat 模式禁止 project Key fallback、MCP URL allowlist、实际 claim 前凭据检查、身份确认 endpoint、任务/actor 关联、完成/取消/权限变化撤销、后端标签与生命周期提示。

**产物：** 分解的小 PR、official 回归、compat 测试、配置与迁移说明。

**验收：** S05/S08/S09/U01 与 A04；旧版本响应不含 mcp.headers 时 official 正常，compat 必须明确失败；排队超过 TTL 的任务不能带过期 token 开始执行。

**说明：** 不能只改 `service.go` 而遗漏真正的 `dispatch.go`；具体任务领取位置由 T01 查证，不虚构 hook。

## T08：MCP 与 HTTP Action 执行

**依赖：** T02、T06。

**操作：** 使用官方 MCP Go SDK；工具发现和执行共享策略；底层通过 HTTP Action API，固定 native connection ID 并使用受限 runtime token；建立 operation ID、Idempotency-Key、UNKNOWN 状态、结果转换与审计关联。

**产物：** MCP 工具、OpenConnector HTTP adapter、限流与超时、注入故障测试。

**验收：** M01–M04、E01–E05；工具 guide 不含内部管理地址/秘密；跨不同 MCP 调用的重试不声称自动可判重；首版默认只读。

## T09：连接生命周期与安全断开

**依赖：** T02、T06、T10。

**操作：** 分离本地禁用、remote revoke、delete；撤权前先阻止新执行；重试与人工处理状态明确；旧 session 不获得新连接权限；将状态同步到 Multica。

**产物：** 生命周期状态机、worker、UI 状态契约、provider 撤权能力说明。

**验收：** R01–R05；不支持撤权不能返回 404 或假成功；真实第三方在途副作用不被声称已回滚。

## T10：OpenConnector 非破坏性撤权补丁

**依赖：** T01、T09 接口设计。

**操作：** 复用原有 revoke 服务，增加按稳定 ID 独立撤权入口；失败保留加密凭据与恢复信息；成功后再由 delete 清理；不改变旧 DELETE 的默认契约。

**特别检查：** provider unsupported、429、网络失败、重复请求、凭据替换竞态、影响同 provider grant 的其他连接、原有 trigger subscriptions 约束。

**产物：** 独立 PR、真实/模拟 provider 测试、结果语义与兼容说明。

**验收：** 底层不是“先删除再尽力撤权”；网关不接触原始 OAuth Token；失败后仍可安全恢复。

## T11：全链路验证与独立安全审查

**依赖：** T03–T10。

**操作：** 执行完整四十项验收；实际目标 Agent CLI 各运行一遍；两用户、两项目、多副本、服务重启、长队列、断网、乱序回调和数据库故障；审查密钥流向与越权边界。

**产物：** 带版本/命令/结果的测试报告、安全审查、已知问题、修复 PR。

**验收：** 所有生产必需用例通过；高影响风险未关闭则不得进入发布；仅 mock 通过的第三方功能明确标记未验证。

## T12：发布、恢复、升级与交付

**依赖：** T11。

**操作：** 构建锁定镜像，提供 TLS/Secret/网络策略/迁移配置，演练新部署、数据恢复、canary、停止兼容模式与 official 回滚；建立依赖升级差异测试。

**产物：** 发布清单、制品摘要、manifest、部署/轮换/恢复/回滚手册和维护说明。

**验收：** U02；恢复不会复活历史会话；写操作 UNKNOWN 不被自动重新执行；任何缺少安全补丁的降级都会停用 compat，而不是退回全权限模式。

8. 第三方写操作只在明确批准的测试资源与账号执行。

10. 不调用、不修改生产凭据，除非另有具体授权。

最终交付包括代码、补丁、四十项验收结果、制品/依赖版本、兼容矩阵、
